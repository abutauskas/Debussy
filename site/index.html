Debussy is an open System 1 decision model. It makes the quick calls an AI agent needs (is this safe, should I call this tool, do I actually know this) in a single pass on an ordinary CPU, and it says “I don't know” when it doesn't.

The model

Three decisions an agent makes all day

Each call returns a probability for every option instead of free-form text, so your code can act on it, set its own thresholds, or send the hard cases to a person.

Safety judge

Is the user's request harmful? Did the assistant refuse? Is the assistant's reply itself harmful? Three answers from one read of the conversation.

wildguard(prompt, reply) → {prompt_harm, refusal, response_harm}

Tool-call router

Given the tools and the request: call the tool, ask the user for the missing details, or say it can't be done.

when2call(tools, request, candidates) → {tool_call, request_for_info, cannot_answer}

Honest knowledge

Picks the right option when it knows, and “I don't know” when it isn't sure. On obscure questions it would rather abstain than guess.

choice(question, options + ["I don't know"]) → {option: p, …}

How it works

System 1, on purpose

No chain of thought and no long generations. Debussy asks a small model short questions and reads its confidence directly.

Read once, ask short questions

The base model reads the input once, then answers a few yes/no questions. Debussy reads the probability of “yes” against “no” instead of generating text.

Calibrate with tiny heads

Small logistic regressions turn those probabilities into calibrated decisions. Which head to use is chosen by cross-validation on training rows only.

Abstain honestly

For knowledge questions, Debussy answers only when its confidence clears a threshold set on a separate practice set, and says “I don't know” otherwise.

◐ Honesty

We publish what didn't work

A decision model is only useful if you can trust its numbers, so we report the misses as carefully as the hits.

  • Estimates, not official scoresEvery number here is our own measurement. We'd welcome an independent evaluation.
  • Below chance on HLE13.6% against 16.4% chance. A System 1 model does not solve these questions, and we don't pretend it does.
  • Two probes that didn't beat simpler rulesReading K2-Horizon's internal state lost to its plain confidence on knowledge (51.8 vs 53.1) and to the calibrated heads on safety (0.927 vs 0.936). We kept the simple versions.
  • Our own check caught usOn random noise, the best of 12 probe settings still “won” plain cross-validation. We now judge every new idea with nested cross-validation.
  • Stale data, re-runAn old batch of calibration rows didn't match a fresh run (most likely it was saved before a bug fix). We re-ran it and re-fitted; the score did not move.
  • Slow on small CPUsAbout 13 s per safety judgement on the 4-core machine it was built on. GPU and laptop numbers are next.
Get started

Try it in a few minutes

Clone the repository, download the 2.7 GB base model, and run the demo. The Duo and K2 variants also need a current build of llama.cpp's llama-server.

View on GitHub Model card 
# get Debussy and the light base model
git clone https://github.com/abutauskas/debussy && cd debussy
pip install llama-cpp-python==0.3.36 numpy pandas pyarrow scikit-learn
mkdir -p models && curl -L -o models/Qwen3.5-4B-Q4_K_M.gguf \
  https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/resolve/main/Qwen3.5-4B-Q4_K_M.gguf

# three demo decisions
python -m debussy.model
